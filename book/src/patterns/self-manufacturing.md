# Self-Manufacturing Ecosystem

How the ecosystem proves manufacture from emptiness, recursively gyms itself, and closes the causal loop.

## 57. Empty Repo Crown ★★★

**Context.** A manufacturing system claims it can create a complete project capability from admitted semantics and qualified packs.

**Problem.** Success on a heavily prepared repository may merely prove hidden manual setup rather than autonomous manufacture.

**Forces.**

- Empty starts expose missing assumptions.
- Real projects contain legacy constraints.
- Bootstrap dependencies still need to come from somewhere.

**Therefore:** **Use an intentionally empty consumer repository or directory as the crown world. From only admitted project semantics, resolved qualified packs, and pinned toolchain, manufacture the project and run its gym to behavioral standing.**

**Consequences.** The demonstration measures manufacturing closure rather than template rendering.

**Falsifier.** The empty-repo scenario requires hand-authored application/config/test glue after generation before the project gym can pass.

**Evidence.**

- [ ] empty baseline identity
- [ ] semantic input
- [ ] pack lock
- [ ] manufacture receipt
- [ ] project-gym ALIVE receipt

**Connects to.** Pack Gym, Project Gym, Delete and Regenerate.

## 58. Delete and Regenerate ★★★

**Context.** A generated repository or artifact tree is claimed to be a projection rather than the primary source of truth.

**Problem.** Manual edits and hidden state can accumulate until regeneration is theoretically possible but practically false.

**Forces.**

- Deleting artifacts feels risky.
- Build caches obscure dependencies.
- Some state is intentionally persistent.

**Therefore:** **Periodically delete the disposable projection and reconstruct it from the canonical graph, pack lock, and pinned toolchain; then rerun behavioral verification under declared equivalence.**

**Consequences.** Regeneration becomes continuously exercised disaster recovery and drift detection.

**Falsifier.** A supposedly reproducible project cannot be rebuilt after deleting generated artifacts without recovering undocumented manual state.

**Evidence.**

- [ ] canonical inputs
- [ ] deletion boundary
- [ ] rebuild receipt
- [ ] artifact equivalence
- [ ] project-gym replay

**Connects to.** Deterministic Projection, Empty Repo Crown, Replay Equivalence.

## 59. GgenGym ★★★

**Context.** ggen itself is the manufacturer for many project classes.

**Problem.** Pack tests prove individual manufacturing processes but do not prove the manufacturer across resolution, composition, refusal, drift, and multi-pack behavior.

**Forces.**

- The manufacturer has a huge state space.
- Testing only happy paths hides systemic defects.
- Self-testing creates recursion.

**Therefore:** **Maintain a first-class GgenGym whose worlds include empty consumers, existing consumers, multi-pack compositions, invalid ontologies, ownership collisions, drift, broken toolchains, and repeat-sync scenarios.**

**Consequences.** The manufacturing engine has an executable laboratory independent of any single pack.

**Falsifier.** A core ggen regression can pass all individual pack fixtures because no system-level manufacturing world exercises it.

**Evidence.**

- [ ] manufacturer identity
- [ ] world catalog
- [ ] scenario families
- [ ] failure fixtures
- [ ] receipts across ggen versions

**Connects to.** Pack Gym, Gym of Gyms, Failure Becomes Law.

## 60. Gym in Every Project ★★☆

**Context.** Projects across the ecosystem need a consistent place for executable examples, playgrounds, acceptance worlds, and capability proof.

**Problem.** Each repository invents a different layout and tooling convention, making discovery and automation expensive.

**Forces.**

- Not every library needs heavy end-to-end tests.
- Uniformity can become dogma.
- A common convention unlocks tooling.

**Therefore:** **Adopt `gym/` as the canonical behavioral proof surface for executable projects and packs. Permit lightweight gyms, but standardize the semantic roles of worlds, scenarios, fixtures, assertions, and receipts.**

**Consequences.** Tooling can locate and execute capability proofs without repository-specific archaeology.

**Falsifier.** A major executable project has no discoverable behavioral proof surface or requires bespoke knowledge to find its acceptance scenarios.

**Evidence.**

- [ ] gym manifest or discoverable convention
- [ ] world/scenario locations
- [ ] runner contract
- [ ] receipt references

**Connects to.** Project Gym, Pack Gym, Gym of Gyms.

## 61. Gym of Gyms ★★☆

**Context.** Many gyms must be compared, composed, or exercised as one ecosystem.

**Problem.** A central runner that hardcodes every domain becomes the new monolith.

**Forces.**

- Cross-gym experiments are valuable.
- Gyms have different lifecycles.
- Federation should preserve local semantics.

**Therefore:** **Build a meta-gym that treats gyms themselves as typed subjects with adapters, maturity, capability matrices, and receipts. Compose through shared lifecycle contracts rather than importing domain internals.**

**Consequences.** The ecosystem can evaluate gym infrastructure and selection policies at a higher level.

**Falsifier.** Adding a new gym requires patching privileged meta-gym core logic rather than registering a compatible typed adapter.

**Evidence.**

- [ ] gym registry identities
- [ ] adapter contracts
- [ ] common lifecycle
- [ ] meta-scenarios
- [ ] cross-gym receipts

**Connects to.** Federated Gym Graph, GgenGym, Autonomic Curriculum.

## 62. Autonomic Curriculum ★☆☆

**Context.** A gym ecosystem accumulates failures, capability evidence, planner performance, and changing worlds.

**Problem.** Static scenario suites stop targeting the most informative uncertainty and repeatedly spend resources on already-settled behavior.

**Forces.**

- Adaptive testing risks moving goalposts.
- Exploration needs reproducible seeds.
- Regression coverage must remain stable.

**Therefore:** **Maintain a stable regression core plus an autonomically selected curriculum drawn from UNKNOWN edges, recent failures, boundary conditions, and high-value uncertainty. Record why each scenario was selected.**

**Consequences.** Evaluation effort follows information value while preserving historical comparability.

**Falsifier.** Adaptive selection can silently drop required regressions or choose scenarios without a recorded objective/evidence rationale.

**Evidence.**

- [ ] fixed regression set
- [ ] adaptive candidate pool
- [ ] selection rationale
- [ ] budgets
- [ ] curriculum receipts

**Connects to.** Planner League, Failure Becomes Law, Cost-Time-Attention Budget.

## 63. Combinatorial Maximalism ★★★

**Context.** The ecosystem can compose many planners, packs, providers, worlds, policies, and formulations.

**Problem.** Humans often collapse the graph early because the full combination space feels intractable, losing potentially superior lawful configurations.

**Forces.**

- Combinatorics explode quickly.
- Most combinations are invalid.
- Machine-state actuation must remain conservative.

**Therefore:** **Preserve the maximal reversible lawful graph in ontology, planning, and construction space; prune with explicit constraints and evidence; delay irreversible selection; and keep all DO transitions behind bounded authority.**

**Consequences.** Machines explore what humans cannot enumerate while consequence remains controlled.

**Falsifier.** The system discards reversible candidates before a constraint or evidence edge justifies the removal, or lets broad exploration expand ambient actuation authority.

**Evidence.**

- [ ] possibility graph
- [ ] constraint/pruning provenance
- [ ] selection record
- [ ] authority boundary
- [ ] comparative evidence

**Connects to.** Possibility Registry, Constraint Fence, Reversible Composition.

## 64. Closed Causal Loop ★★★

**Context.** The ecosystem has discovery, planning, manufacture, execution, evidence, and learning components.

**Problem.** If these components exchange prose or ad hoc files rather than shared identities and receipts, failures cannot improve future manufacture and selection.

**Forces.**

- Different systems optimize different concerns.
- Loops can amplify bad inference.
- Canonical state and behavioral evidence have different roles.

**Therefore:** **Close the loop: admitted knowledge graph → executable world → observed event evidence → analysis → hypothesis/intervention portfolio → bounded experiment → consequence → verification → receipt → learned law → deterministic manufacture → new world state. Keep observation, inference, authority, and actuation typed throughout.**

**Consequences.** The ecosystem becomes self-improving without making the model or planner the authority source.

**Falsifier.** A failure or successful experiment cannot be traced into a changed selector, constraint, pack, verifier, or manufacturing law.

**Evidence.**

- [ ] shared subject identities
- [ ] event/receipt spine
- [ ] explicit learning transition
- [ ] updated law/projection
- [ ] subsequent verification

**Connects to.** Failure Becomes Law, GgenGym, Release Crown.
